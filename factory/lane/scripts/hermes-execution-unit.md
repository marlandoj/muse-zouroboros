## Concrete caller

The exact generated `zouroboros-factory-execution.service` runs the root-owned `hermes_execution_unit.py` with an independently approved input SHA. It validates its actual active unit, MainPID, invocation, unified cgroup, read-only cgroup mount and kernel memory/process limits before calling the reviewed `hermes-execution-supervisor.py:execute_once`. The supervisor retains the issuer lock, authenticates the committed selected-content artifact, checks subscription status, and hands only that exact packet to its nonprivileged Bun child. Root-private cap consumption is durable before the first worker reservation grant. The child uses the existing journal and single-launch runner. Every result remains held.

The service uses a nondelegated cgroup with a finite runtime (180â€“600 seconds; default proposal 300), `KillMode=control-group`, a 3-second stop timeout and final SIGKILL. Creating a new session/process group does not escape this manager-owned cgroup. The supervisor's own group cleanup remains useful but is not the service containment boundary. No automatic restart, timer, socket activation or `[Install]` target is generated. The unit intentionally omits `User=root` while retaining `Group=root`: systemd259 removes effective CAP_SETUID during explicit-user/seccomp setup before NoNewPrivileges prevents its restoration. Both wrapper and worker verify the actual root MainPID UID/GID, cgroup, permitted/effective/bounding capabilities and zero ambient/inherited capabilities. An empty manager User field alone is never proof of root identity.

## Proc protection and trusted bootstrap

The authenticated root supervisor and nonprivileged Bun bootstrap run before the adapter sandbox. They are trusted source, not a security boundary for arbitrary code: proc path masking now applies to the adapter and its descendants, rather than to the whole outer service. Neither the adapter nor selected repository code may execute before `prepareManagedFactorySpawn` constructs that boundary. The existing pinned-source checks, capability limit, UID drop, no-new-privileges, finite lifetime and cgroup cleanup remain required.

On the qualified Linux 7.0/systemd 259 host, `ProtectKernelTunables=yes` and `ProtectKernelLogs=yes` add locked child mounts under proc. Either independently prevents Bubblewrap 0.11.1 from mounting proc for its new PID namespace. The unit explicitly disables those two outer proc masks, preserves `ProtectKernelModules=yes` and `PrivateDevices=yes`, blocks the `syslog` syscall, and recursively binds `/sys` read-only. `ReadOnlyPaths=/sys` was observed ineffective against systemd's implicit writable API-filesystem exception, so the exact required setting is `BindReadOnlyPaths=/sys`.

Bubblewrap keeps `--unshare-pid` and creates a new proc filesystem. Before executing any adapter, it masks `/proc/{kallsyms,kcore,kmsg}` with read-only `/dev/null` binds and remounts the whole private proc read-only. This covers all proc tunables, including entries beyond Bubblewrap's default list; there is no host proc bind and no additional capability. The worker's view of `/sys` is absent. Systemd's syscall filter kills a forbidden `syslog` call; qualification performs that test in a disposable child.

Wrapper and worker require the exact loaded replacement settings plus actual read-only `/sys` and cgroup state. The worker opens each checked directory and uses kernel `mnt_id` from its descriptor's `/proc/self/fdinfo` to select the visible mount record. Hidden lower mounts and mountinfo row order cannot substitute for the visible read-only mount.
